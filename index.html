ℹ️ About — Pack Checker
📋 وصف الأداة

الهدف: التحقق من تغليف الأوردرات قطعة قطعة قبل الشحن، وتسجيل التغليف على الأوردر (ميتافيلد + tag) وفي سجل D1.

المستخدمون المستهدفون: موظفو التغليف في المخزن — بالسكانر أو بالإدخال اليدوي.

كيف تعمل — Workflow

  1. سكان باركود الأوردر أو إدخال رقمه → الـ Worker بيجيب بيانات الأوردر من Shopify.
  2. الأداة بتحدّد المرحلة (S1/S2) من تلات إشارات: وجود طلب استبدال نشط + custom.manual_status + custom.status_2_r_e.
  3. لو الأوردر متغلّف قبل كده من غير تعديل: نافذة بتعرض تفاصيل التغليف السابق وبتمنع الإعادة.
  4. لو متغلّف قبل كده ومع تعديل مكتشف: نافذة واحدة بتجمع التفاصيل + تأكيد رجوع المخزون، وبعد التأكيد بتكمّل.
  5. سكان منتجات الأوردر واحدة واحدة بالباركود/SKU → لما تكتمل → زرار «تأكيد اكتمال التغليف».
  6. الـ Worker بيكتب الميتافيلدات + tag، وبيسجّل في D1 ومعاه بصمة المنتجات للمقارنة المستقبلية.

FEATURE MAP

  • §AUTH (Worker) — بلوك الدخول المشترك · §AUTH-JS (HTML) — شاشة الدخول والخروج
  • §PACK::analyzeStage (Worker) — تحديد المرحلة من التلات إشارات
  • §PACK::classifyOrderItems (Worker) — تصنيف المنتجات على fulfillableQuantity
  • §PACK::buildFingerprint + readStoredFingerprint (Worker) — كشف التغيير
  • §PACK::fetchOrderForPack (Worker) — تصفيح lineItems و returns + علم truncated
  • §DIAG (Worker) — diag وget_config
  • §SCAN (HTML) — سكانر الأوردر وسكانر الباركود
  • §TOOL-JS (HTML) — شاشة الفحص · النوافذ · نتيجة التغليف بـ ٣ حالات
  • §LOG-JS (HTML) — جدول السجل · الفلاتر · الترتيب · الصفحات · تصدير XLSX

KEY VARIABLES

  • TOOL_VERSION — مصدر واحد لرقم نسخة الواجهة (الهيدر + الـ Changelog + شاشة الدخول)
  • MIN_WORKER_VERSION — أقل نسخة Worker الواجهة دي بتشتغل معاها (مالهاش علاقة بـ TOOL_VERSION)
  • WORKER_URL · ADMIN_WORKER_URL — ثوابت في §CONFIG، مش في الإعدادات ولا localStorage
  • LS_SECRET = 'pack_checker_worker_secret' — المفتاح الوحيد في localStorage
  • currentEmployee — { username, displayName } في الذاكرة فقط
  • msState — حالة فلاتر الاختيار المتعدد في تاب السجل
  • TOOL_NAME = 'pack_checker' — قيمة tool في جدول logs

NOTES / QUIRKS

  • كشف التغيير بيقرا extra.fingerprint المخزّن؛ الصفوف القديمة بترجع لتحليل نص items — ولو التحليل فشل، النتيجة «فيه تغيير» (الافتراضي الآمن).
  • صيغة items (SKU ×qty) مرتبطة بين complete_pack وget_order — الاتنين بيتغيّروا مع بعض.
  • fulfillableQuantity هو مصدر الحقيقة الوحيد للتصنيف — ممنوع فلترة يدوية على الـ refunds.
  • dateFrom/dateTo بيتقارنوا بـ timestamp المخزّن (UTC) والعرض بتوقيت القاهرة (UTC+3) — فرق ٣ ساعات ممكن يحط عملية متأخرة في يوم UTC اللي بعده.
  • edit_count لسه في schema الـ D1 للتوافق بس — مابيتكتبش من v1.3.0+.
